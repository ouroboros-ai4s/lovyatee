# Surface Metric Computability And Claim Strength Run Opposite

## description

按输入需求把界面描述子排成一列，会看到一个反序：**所需输入越少，可算的记录越多，能支持的结论越弱。**

| 指标 | 所需输入 | 能回答的问题 |
| --- | --- | --- |
| Zernike、surface histogram | 单体结构 | 这个整体表面形状在别处出现过吗 |
| 全复合物对齐（US-align 等） | 两个伙伴 + 映射 | 这整个复合物有没有同构复制 |
| 接触集 / DockQ 分量 / iAlign | 两个伙伴的排布 | 这条抗体接触了哪些残基 |
| 逃逸谱 | 突变库 + 中和读数 | 这个界面在功能上是否可区分 |

单体结构在手时，第一行可算，下三行不可算。而第一行回答的问题与「这批数据覆盖了多少表位」不同类 —— 表面形状相同不推接触集相同，反之亦然。

**这是本条新增的部分**：这不是精度差异可以弥合的东西。加更好的描述子、加更长的训练、加更大的模型，都不会把单体结构变成伙伴排布。所以「我们为全部记录都算了表面描述子」这句话里的「全部」是一个假覆盖 —— 覆盖面统计的是有多少条记录拿到了一个数，而不是这个数能否支撑目标结论。目标结论需要的是接触集，而接触集只在那 20% 有复合物结构的记录上可算。

数值形式（我构造）：设 100 条记录中 80 条只有单体结构、20 条有复合物。Zernike 覆盖率 100%，接触集覆盖率 20%。若报告写「表面多样性已全面测量」，字面属实，但支撑结论的样本量是 20，且这 20 条不是随机的 —— 有复合物结构的记录系统性偏向被反复研究的抗原。所以有偏的不只是精度，还有被认证的那一部分的构成。

**顺带得到的第二个结论**：可算性不能用作筛选替代。按「能算就纳入」筛选，等于按「输入富集程度」筛选，而输入富集与测量对象无关。这与 [[predicted_structures_add_no_classes_beyond_the_reference]] 是同一类错误的不同层：那条说 P ⊆ E 时补进去只增样本量、不增类别；本条说补进去的那批样本可能连 E 都没碰对。

条件方向：**必要**是分列报告「可算记录数」与「能支撑目标结论的记录数」—— 两者可以差一个数量级，合并报会把假覆盖读成真覆盖。**不充分**是即使分列报出，也不能推出有复合物结构的那 20% 对全部抗原族有代表性；要得到代表性还须另做留出检验。

可操作要求：每个界面指标标注所需输入档位；覆盖分母一律取「具有该档输入」的记录数，不取总记录数；跨档比较时明写两档之间不存在精度换算。

可证伪内容：若存在一个只用单体结构输入即可计算、且在已知复合物结构的留出集上与接触集判据给出相同冗余判决（逐对一致率显著高于随机）的描述子，则可算性与结论强度在该任务上不再反序，本条失效。

边界：若目标问题本身就是「表面形状在结构数据库中是否重复」，第一行的指标就是恰当的，反序不构成缺陷；本条只针对「表位 / 界面覆盖」这一类目标。
