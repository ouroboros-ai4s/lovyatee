# Similarity Structure Is Not A Certificate

## time

## description

`S = Measure(D, O, X)` 与 `C = F(S, R, V, T, M)` 是两层，不是一份文档的两个字段。产物边界应从这条分离直接推出：

**S 是唯一可复用的对象，`C` 是从 S 派生的。** 因此 S 的寻址键只能是 `(D, O, X)` 的摘要——三个槽，不是七个。证书持有 S 的摘要指针，加上它自己用到的 `(R, V, T, M)` 具体值。原型把整份 declaration（含 `R`、`V`、`T`、`M`）哈希后绑到相似性产物上，后果不是性能问题而是能力缺失：同一份 D、同一个 X，只改参考域，也必须整张矩阵重算；而本项目最需要问的问题——**同一个相似性结构在不同 R 下是否给出不同结论**——在该寻址规则下无法被提出，更无法被回答。

由此得到三条产物规则：

1. `measure` 的输出只依赖 `(D,O,X)`，可以被任意多次 `evaluate` 复用；复用次数本身是研究产出（一个 S 支撑了几个 R）。
2. 证书必须记录它引用的是哪个 S 摘要，且当 S 被重新生成（同名不同内容）时，旧证书不能静默继续有效。
3. `F` 是纯函数：同 `(S, R, V, T, M)` 必须给出同一证书字节。任何随机性（抽样、种子）属于 `X` 或 `V` 的声明，不属于 `F`。

**边界**：若 `X` 本身依赖 `R`（例如按参考集归一化、按参考分布校准阈值），则 S 不再对 `R` 独立，必须按 `(D,O,X;R)` 重新生成，并在 `X` 里显式声明这一依赖。此时分离仍然成立，只是键长度变为四。

**可证伪内容**：若实测表明按 `(D,O,X)` 缓存的 S 在实际研究流程中从不被第二个 `R` 复用，则这一层分离只有概念价值，没有工程价值；若 `X` 在目标用例中全部依赖 `R`，则缓存键必须退回七槽，本条的操作性主张失效。
