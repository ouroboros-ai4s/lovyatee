# Collection Breadth Requires A Held Out Antigen Assay

## description

Cohen 2021 用展示多种冠状病毒 RBD 的 mosaic 纳米颗粒免疫小鼠，并在**包含免疫原之外抗原**的面板上测量所引发应答的交叉反应广度。原文支持一个验收方式的判断：评估一批抗原的多样性应做前瞻性广度试验，而不是数不同抗原序列。

理由是（部分为我的表述）：序列计数把抗原当可交换单位，忽略共享表位。两个序列不同的抗原可能覆盖同一表位空间，此时按序列计数会把它们算成两份多样性；反之，序列高度相似的两个抗原可能暴露不同表位。广度是「对集合外项目的泛化」，只有留出抗原上的实测能给。

这把 [[annual_antigen_targets_require_marginal_interface_coverage_estimates]] 所要求的独立批次验证换成了一个可执行的实验形态：不是回顾性估计覆盖增量，而是主动构造一个已知抗原集合、免疫、再在留出面板上测广度。

两条边界不能省。其一，mosaic 制剂同时改变展示价数与几何；若未与同型、同总价数的对照匹配，广度差异不能单独归因于抗原多样性（见 [[cross_reactivity_breadth_is_not_a_function_of_the_antibody_alone]]）。其二，读出是鼠抗体应答；搬到「数据集该收多少」需要额外假设「留出抗原上的应答广度就是我们想评估的目标」—— 这是待检验假设，不是原文结论。

可操作要求：报告广度时同时给免疫原集合、留出面板的构成与选择依据、价数对照、以及读出层次（结合 / 中和）。

具体构造（我构造）：集合 S₁ 含 5 个抗原、S₂ 含 8 个，但 S₂ 的 8 个里有两个只在前一个的基础上换了单点突变。按序列计数 S₂ 有更大多样性；按留出面板上的实测广度，两者可能给出相同甚至相反的顺序。要判这一点，只需要这两个集合的留出广度读数，不需要新方法。

条件方向：**必要**是在留出抗原上实测广度 —— 序列计数无法排除「两个不同序列覆盖同一表位空间」，这是本条论证的直接后果。**不充分**是即使做了前瞻性广度试验，结果仍绑定在所用留出面板与读出层次上（结合 vs 中和）；所以「测了广度就得到客观抗原多样性」不成立，面板构成本身是待声明的自变量。

可证伪内容：若跨制剂实测广度的排序被「集合内不同抗原数」完全预测（秩相关为 1 且无残差），且留出抗原试验不追加任何信息，则数抗原已足够，本条被推翻。
