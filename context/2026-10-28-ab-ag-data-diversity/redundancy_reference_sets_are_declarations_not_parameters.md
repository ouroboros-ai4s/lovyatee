## description

同一条记录在三份父记录里分别要求「固定参考库」「同一条参考记录」「标定搜索范围」。合起来会发现一件父记录都没说的事：**参考集不是可扫描的参数，它是声明；但它的效应与 τ 这类可扫描参数完全同级，甚至更大。**

要把这一条说清楚，得先把「参数」与「声明」分开。参数是一维的、有自然序的量：τ 从 0.5 走到 0.8，单调，可以扫。参考集不是一个量 —— 换一个参考库不是「把某个值调高一点」，是换掉整张对照表。所以对参考集做「稳健性扫描」是无定义的，而它引起的判决变化却比任何参数都大。

具体构造（我构造，可直接复算）。查询集合 Q 含 3 条记录，判定「与参考库中任一记录的相似度 ≥ τ = 0.6 即冗余」：

- 参考库 R₁ 含 {q 的近邻}，三条全部命中 → 冗余率 3/3；
- 参考库 R₂ 删去那一条近邻、其余不动，三条全部不命中 → 冗余率 0/3。

同一批查询、同一阈值、同一相似度定义，冗余率在 0 与 1 之间。τ 的稳健性扫描在 R₁ 上给出的是「τ 在 0.55–0.65 之间都不变」，在 R₂ 上给出的也是「不变」—— 两次扫描都稳健，结论相反。

**这一步是父记录都没有的**：联合冗余那条要求「同一条参考记录同时满足两侧」，说清了判据的形状；反演那条要求先固定参考库，说清了前提；未决那条把未决分成两类。但三条都没说参考集的切换不属于可扫描的轴，因此稳健性报告的写法本身有缺陷。

由此得到可操作的替换规则：**稳健性报告里，参考集的地位等同测量对象，不是等同阈值。** 报告冗余率时，必须同时给参考库的构成与边界（哪些记录在内、按什么规则入选、版本或时间截断），并把「换一个参考库后该数会怎样」作为独立小节，而不是作为阈值扫描的一个维度。

还有一层与反演的联系。[[accuracy_based_redundancy_estimates_require_independent_calibration]] 的反演式 π = (A−b)/(a−b) 里，a 与 b 都是在**给定参考库**下校准的。换参考库，R 的定义变，a 与 b 变，反演出的 π 也变 —— 所以「π 的校准」这个说法必须带上参考库，不能只带 a、b 的数值。这与 M 类字段（[[model_scores_add_a_fourth_undeclarable_field_class]]）遇到的是同一个问题：一个不可扫描的声明被当成可扫描的参数来报稳健性。

条件方向：**必要**是报出参考库构成与入选规则 —— 上表给出同一批查询在两个合理参考库下冗余率从 0 到 1 的直接构造，不报就无法解释任一个数。**不充分**是报出构成也不够：两个都合理的参考库给出相反结论时，没有规则裁定哪一个对，只能声明本次审计采用哪个、以及为什么它是目标总体。

可证伪内容：若存在一类参考库族，使得同一批查询在其上任意两个成员下算出的冗余率之差，95% 置信区间完全落在 ±0.05 内，则参考集在该族上退化为可忽略的自由度，本条对该族失效。

边界：参考库由外部标准固定且不可选（例如法规指定的公共数据库快照）时，本条退化为「记录版本号」，不构成待裁决的声明。
