汇总日期：2026-10-20。共享存储 `data/raw/public/` 下已接入的全部数据源（含 R24 / R39 / R52 / R55 等尚无 README 的占位目录）整理为下面一张表。每个数据源的调研摘要、磁盘现状与 README 全文已拆成单独文件，放在 `2026-10-19-ag-ab-affinity-dataset-readme/`，由表中「数据集」列的链接指向。编号 R68 未出现在汇总中。

三类信息来源，互相独立标注：

1. **调研摘要**：来自《2026-09-15 抗体结合排序 数据收集与模型建设计划》第 3 章逐项资源条目（调研截止 2026-09-14，仅覆盖当时收录的 66 项；R67 及之后的数据源在计划文件中没有条目）。
2. **下载清单状态**：来自《2026-09-15 补充列表下载任务》对 R11 之后数据源的分类。该清单是 9 月中旬的任务状态，**不代表当前磁盘现状**；若与磁盘不符，以磁盘为准。
3. **磁盘现状与 README 全文**：来自 ab02 上 `/data/shared/CX029_binding_ranking/data/raw/public/<source_id>/<version>/` 的实际目录统计（字节数为文件内容总和，不含 `.staging`）和该目录下 `README.md` 的原文。README 原文几乎逐字收录，处理仅限：删除各自文首的目录、标题层级调整、R26 省略 6 行总计约 25 万字符的嵌入向量逐维度列名。拆分时只把标题整体上提两级，使每个文件以 `#` 开头。

> 注意：数字（行数、序列数、KD 个数等）全部引自各 README 或调研文件，没有重新核算；R01 与 R02 的处理规范（`data_processing/r01_igdesign.md`、`r02_absci_her2.md`）才是按实际 CSV 重新核算后的口径。不同数据源的「数量」可能分别指序列数、分子配对数或测量次数，不能直接相加。
>
> 体量与文件数统计的是 `raw/public/<source>/<version>/` 目录，包含论文 PDF、PDB 参考结构、Git 快照内的 `.git` 以及大体积原始数据（FASTQ、模型输入归档等），不是纯表格数据量。R10、R19、R31、R50、R70、R72、R73 等体量远超表格本身，主要由结构、FASTQ 或模型输入归档构成，具体构成见各自 README 的「仓库内容」。

## 附录 A：规模、重复与结构覆盖（计划文件第 4 章，原文）

这一章回答三个问题：公开数据大概有多少，怎样判断不同记录是否来自相互独立的实验，以及目前能确认哪些记录配有实验测定的结构。数据库给出的数字只有在统计对象相同时才可以比较。序列数、抗体—抗原配对数、测量次数和文件行数代表不同含义，也不能直接换算成最终可用于训练的样本数。

---

### 公开数据大致有多少

从已经核实的资源看，**与从头设计抗体最接近、同时具有序列和直接测量结果的数据，目前主要是几百到约千条；经实验校准的亲和力估计、有序类别和其他连续实验信号可以达到数万至数十万条；二元结合配对也可以达到数十万条。** 个别研究或目录给出的规模达到数百万甚至数千万，但其公开文件是否完整、记录是否独立以及标签能否直接使用，仍需分别确认。

| 监督信号或记录类型 | 已确认的代表性规模 | 使用前需要确认什么 |
|-|-|-|
| 设计抗体的直接 $K_D$ 测量 | IgDesign 有 321 行数值 $K_D$，其中包含 7 行对照；Absci HER2 有 421 个设计候选和 1 条参考记录，均有有限 $K_D$ | IgDesign 主要公开 HCDR 序列；Absci 数据偏向已通过筛选的结合者，不能代表全部设计的成功率 |
| 免疫来源抗体的同抗原排序数据 | KyDab 有 1,544 条条件特异的数值 $K_D$ 记录，涉及约 960 个不同抗体；加上 HTRF 和 ELISA，共约 1,465 个不同抗体带连续实验信号 | 123,527 是主表记录数，不是带标签抗体数；不同研究、分析物、pH 和实验方法必须分组；约 910 个抗体同时具有完整双链序列和数值 $K_D$ |

数量依据见相应资源及原始来源。

数据是否丰富，还取决于它覆盖多少个可比较的实验组、多少种独立抗体背景和多少个不同抗原。一万个高度相似的候选，与来自许多不同体系的一万个候选，对模型提供的信息并不相同。用于排序时，同一组 $N$ 条记录虽然可以组成大量比较对，但这些比较对仍然只来自原来的 $N$ 条记录，不会增加独立实验的数量。

抗原侧突变的可用量目前尚未单独统计。AVIDa-hIL6 的 573,891 个配对同时包含原始抗原和突变抗原；AB-Bind 与 SKEMPI 的总量也混合了抗体侧突变、抗原侧突变和其他蛋白质相互作用。因此，上表中的总数不能直接解释为抗原突变样本数。

### 去重后预计能留下多少

在正式下载、统一字段并逐条去重以前，只能给出范围估计。下面的估算把一个“抗体或 VHH—抗原—实验标签”视为一条配对记录：同一个候选面对不同抗原时保留为不同记录；同一次测量被多个数据库重复收录时只计算一次。估算排除了普通 PPI、没有实验标签的序列、纯计算数据，以及公开文件范围仍未确认的 Li 2023 和 SEPIA 超大数据。Porebski 已公开处理后数据包，因此约 24 万条 HER2 数据计入基础估算；HEL、IL-7 和第二轮 HER2 数据在完成文件级核对前只计入上限。

| 逐步收紧的筛选条件 | 预计去重后规模 | 估算依据和主要不确定性 |
|-|-|-|
| 有实验依据的抗体或 VHH—抗原标签 | 约 110 万—190 万条配对记录 | 主要来自 AVIDa 系列、Porebski、RESP、AlphaSeq、Phillips 及若干较小实验；下限计入 Porebski 的 HER2 主数据，上限进一步计入 HEL、IL-7 和第二轮 HER2 处理中能够对应序列与标签的记录 |
| 不同的抗体或 VHH 氨基酸序列 | 约 45 万—130 万条 | 同一条 VHH 可能与许多抗原突变体配对，因此序列数会小于配对数；Porebski 各实验之间的序列重叠和公开字段完整性尚待文件级核对，部分资源也只公开 HCDR 或缺少完整链 |
| 能在同一实验组内用于强弱排序的记录 | 约 40 万—130 万条 | 包括数值亲和力、校准后的表观 $K_D$、有序类别和经过验证的连续实验信号；上限取决于 Porebski 的 HEL、IL-7 和第二轮 HER2 处理数据能够保留多少可用记录 |
| 带数值 $K_D$、拟合 $K_D$ 或校准后表观 $K_D$ 的记录 | 约 13 万—16 万条 | 主要由 AlphaSeq 的 71,384 个候选和 Phillips 约 6.7 万行高通量拟合结果构成，另有 Tite-Seq、MAGMA-seq、IgDesign、Absci HER2 等较小数据 |
| 采用 SPR、BLI 等方法直接定量的记录 | 约 3,000—4,500 条 | KyDab 新增约 1,544 条条件特异的数值 $K_D$ 记录；不同抗原、抗体形式、分析物和实验条件仍需分组，部分记录还缺少完整序列 |
| 最贴近从头设计抗体且有直接定量结果的记录 | 约 700—1,200 条 | 核心来自 IgDesign 和 Absci HER2，并可能加入 Porebski、RFdiffusion、AIntibody 等研究中能够完整对应序列的定量候选 |

估算依据为前述资源的原始研究、公开文件和已经完成的文件计数。

这些范围不是相互独立后再相加的几组数据，而是逐步收紧筛选条件后得到的“漏斗”。对当前任务最现实的预期是：**约 110 万—190 万条去重配对可以支持广义的结合学习，约 40 万—130 万条可以提供某种强弱顺序，而最适合检验从头设计抗体亲和力的直接定量数据大约只有 700—1,200 条。**

KyDab 的约 12 万条免疫组库记录没有整体计入上述“有实验依据的结合标签”范围。只有实际进入 SPR、HTRF 或 ELISA 的抗体才能贡献结合监督；未检测序列既不是实验阴性，也不能据其未被下选推断结合强弱。KyDab 增加了约 1,465 个带连续实验信号的天然免疫抗体，但不会相同比例增加从头设计抗体的直接评价数据。

这个估算最容易受三件事影响：Porebski 公开处理数据中的序列、实验标签和批次能否逐条对应，AVIDa 中同一 VHH 面对多个抗原版本时如何划分训练和测试，以及 IgDesign、Absci 等只公开部分抗体序列的数据能否可靠补全。若以后能够取得并核实 SEPIA 的完整数据包，广义结合配对数可能再增加一个数量级；由于这些记录集中在人工表位和 VHH 体系中，它们不会按相同比例增加适合常规从头设计抗体亲和力评价的数据。

### 为什么不同数字不能直接相加

公开资料常用不同单位描述数据规模。整理训练集前，需要先确定每个数字究竟统计了什么：

| 统计单位 | 表示什么 | 同一对象为什么可能对应多条记录 |
|-|-|-|
| 不同序列数 | 去重后的氨基酸序列数量 | 同一序列可能与多个抗原配对，也可能在多个条件下测量 |
| 候选数 | 研究中制造或评价的分子数量 | 一个候选可能使用 Fab、IgG 等不同形式，或者接受多次实验 |
| 抗体—抗原配对数 | 一个抗体与一个抗原组成一个配对 | 同一抗体与多个抗原测试时会产生多个配对 |
| 测量记录数 | 一次实验或一次拟合得到的一条结果 | 同一配对可能有重复实验、不同浓度、不同批次或不同测量方法 |
| 文件行数 | 整理文件中的记录行数 | 可能同时包含原始记录、重复实验、汇总值、模型预测或上游数据库副本 |

最终样本量需要根据任务定义。例如，训练“是否结合”模型时，一个抗体与两个抗原的实验通常应算作两个配对；训练亲和力排序模型时，同一配对在相同条件下的重复测量应保留重复信息，并在建模时估计或汇总测量误差，而不应被当作多个相互独立的候选。

### 重复测量、相同行和重复收录有什么区别

同一个候选接受多次实验，产生的是**重复测量**。重复测量可以反映实验误差，通常应保留实验批次和每次结果。同一次测量被多个数据库收录，产生的是**重复收录**；如果不去重，它会在训练中被反复计算。还有一种情况是，整理表删除了批次、核酸序列等字段，使原本不同的记录变成完全相同的行。遇到这种**相同行**，需要回到原始数据判断它属于哪一种情况。

Tite-Seq 可以说明为什么完全相同的行不一定是错误。其 11,052 行包括 11,038 条拟合记录和 14 条汇总值；简化后的表中有 5,248 条重复行可以追溯到重复实验及同义编码。“同义编码”是指不同的核酸序列产生了相同的蛋白质序列。整理文件只保留蛋白质序列和简化标签后，这些原本不同的实验记录就会看起来完全相同。因此，不能仅凭整行相同认定原始数据录入有误。

在 80 个可以读取的 FLAb 文件中，7 个文件合计有 6,105 条重复行。这里的计数方法是：每组完全相同的行保留第一条，其余行计入重复行数量。其中 5,248 条来自 Tite-Seq；其余 6 个文件合计 857 条，具体原因尚未全部确认。这一结果描述的是整理文件中内容完全相同的行，不能解释为已经发现 6,105 条错误数据。

| 含有完全相同行的文件 | 重复行数 |
|-|-|
| Tite-Seq 滴定整理表 | 5,248 |
| MAGMA-seq 二元表 | 488 |
| MAGMA-seq $K_D$ 表 | 21 |
| Kirby 二元表 | 344 |
| Hutchinson top200kd_fab 表 | 2 |
| Ab-CoV $K_D$ 摘录 | 1 |
| Zimmermann 摘录 | 1 |
| 合计 | 6,105 |

Hutchinson 的 top200kd_fab 表也说明了文件名不能代替实际计数。该表实际有 50 行、48 种 HL 组合，不能因为文件名含有 top200 就认定它包含 200 条测量。

### 哪些资源之间已知存在重叠

下面列出的关系不一定表示两个资源完全相同，但说明它们共享上游实验、结构或记录。划分训练集和测试集时，需要沿着这些关系继续追溯。

| 已知关系 | 需要怎样处理 |
|-|-|
| FLAb 与 IgDesign、Absci HER2、Tite-Seq 等原始研究 | 为同一实验的不同整理版本记录相同的原始实验标识 |
| AbRank、AbBiBench、ASD、ANDD 与各自的上游资料 | 不能只按数据库名称划分训练集和测试集 |
| AB-Bind、SKEMPI、DACUM、Graphinity 实验子集及历史数据库 | 同一突变测量、换算值和清理版本不能算作多个独立实验 |
| Engelhart 与 Li 2023 | 区分被再次使用的训练数据和后来产生的新设计验证数据 |
| Mason 与 RESP 仓库 | RESP 中的 Mason HER2 副本仍属于 Mason 的原始实验 |
| PDBbind 与 BIORAD | 修订值与原值来自同一测量，需要保留数值版本之间的关系 |
| 各冠状病毒抗体汇编 | 文献、抗体、结构和测量可能重复，需要追溯原始出处 |
| PDBbind、SAbDab、AVIDbase、Guest、DIPS 等结构资源 | 相同结构或高度相关的复合物可能跨库出现，容易造成测试集信息泄漏 |

去重时应追溯到**同一次实际测量**。抗体名称或蛋白质序列都不足以单独确定测量身份。相同序列在不同抗原、不同分子形式或不同实验条件下得到的结果应分别保留；同一次测量被多个资源引用时，则应记录共同的原始来源，避免重复计入。

## 附录 B：使用方式与仍待确认的缺口（计划文件第 5 章，原文）

### 先保留每条记录的来历和测量条件

选定来源后，重要的是让每条记录都能够回答“谁和谁、在什么条件下、测出了什么”。只留下序列和一个分数，往往会丢失决定这条数据能否使用的信息。

| 要保留的信息 | 具体包括什么 | 有什么作用 |
|-|-|-|
| 原始出处 | 论文、原表位置、数据版本、重复实验编号 | 识别同一次测量的不同副本，必要时找回原始结果 |
| 被测分子 | 完整抗体序列及形式、实际目标版本、参考分子 | 确认输入与实验结果对应，避免把不同分子混在一起 |
| 变化对象 | 抗体侧、抗原侧或双方变化，以及各自的参考分子 | 区分不同方向的比较；相关抗原的名称差异不能代替突变证据 |
| 实验结果 | 测量类型、数值或类别、单位、方向、误差及上下限 | 确定能做定量比较、粗略排序，还是只能判断是否结合 |
| 状态与条件 | 是否表达成功、实验是否完成、是否检出结合，以及主要测量条件 | 区分不同失败原因，判断哪些候选能够公平比较 |
| 结构与许可 | 结构对应对象、实验或预测来源、数据使用条款 | 判断是否可以加入结构信息，以及是否允许计划用途 |

记录的来源、分子身份和测量含义明确后，才能判断它适合用于分类、排序、定量参考还是结构辅助。若要引入普通 PPI、VHH 等其他类型的数据，需要考虑它们与传统抗体的差异，并在实际任务上检验是否有帮助。

### 同实验排序的优势和适用条件

同实验排序关注一组候选内部的相对强弱，可以减少对跨实验绝对数值一致性的依赖。判断哪些抗体候选属于同一比较组，需要确认目标版本、抗体形式、测量指标和主要实验条件是否一致。组内结果可比较时，可以用它们学习相对顺序，无需先将所有实验的数值统一到同一尺度。

比较不同抗体时，应明确它们面对的是同一个抗原版本；比较不同抗原变体时，应明确测量使用的是同一个抗体。两类比较可提供互补信息，评价结果应分别报告。抗原侧数据能否帮助预测新设计抗体，需要用固定目标、比较不同抗体的实验结果检验。

实验条件一致，并不保证代理信号一定按真实亲和力排序。样品中的有效抗体数量、多点共同结合、实验信号饱和，以及结合与解离速度的差异，都可能改变候选顺序。采用排序方法无法自动消除这些影响。判断结果是否可比，需要检查具体测量，不能只看候选是否来自同一论文或同一团队。

具体能比较到什么程度，取决于实验提供了多少信息：二元标签只区分结合与不结合，有序类别只给出类别间的顺序，超出测量范围的结果只提供上下限。即使记录中有数值 $K_D$，也要检查它是否为量程边界或人为替代值。**排序应限于实验能够支持的差别，不能为未被观察到的差别赋予精细顺序。**

---

### 评价要与将来使用模型的场景一致

评价时应分别考察两项能力：筛出能够结合的候选，以及在已经结合的候选中选出更强者。一个模型可能善于识别表达不好或明显不结合的样品，却不擅长区分真正结合者之间的细微差异。因此，不能只用一个整体相关系数概括这两项能力。

候选与训练数据相似到什么程度，是评价的另一个关键因素。可以区分三种情况：同一参考抗体附近的变体、同一目标上的新抗体家族、模型从未见过的目标。将高度相似的数据随机按行划分训练集和测试集，往往只能检验第一种情况。评价新设计时，应检查训练数据是否通过其他数据库包含了评价候选及其近亲、同一原始测量或相关结构，避免这些重叠高估模型能力。

统计评价结果时，需要保留测量之间的关系。重复测量可以帮助估计实验噪声。共享候选的比较对彼此相关，不能全部视为独立证据。最终应考察模型对独立候选的判断是否改善，以及这种改善能否得到与实际用途一致的定量实验支持。

### 获取数据时，哪些事项仍需确认

本报告以原始论文、作者仓库、机构数据库和正式存档为主要依据。66 项资源覆盖了与任务相关的主要类型，调查范围并未穷尽所有论文。对于动态仓库和新兴研究，尚未确认的数量明确标为待确认。

OAS 抗体序列库、BindingDB 以小分子为主的数据、STRING 相互作用网络提供的是其他类型的信息：序列数量不能当作亲和力测量数，小分子结合记录不能当作抗体—蛋白结合记录，网络关联也不能直接当作实验结合证据。因此，本报告不将这些资源的全库规模计入上述可用量。稳定性、表达、非特异性和功能结果可帮助理解抗体的其他性质，整理时应与目标结合标签分别记录。
