3A = Antibody · Antigen · Affinity：一个抗体、一个抗原，以及两者之间的全部亲和力测量。

3A
I — Problem & Stance

The Problem We Solve

公开的抗体–抗原亲和力数据分散在许多数据集里，同一对分子常被重复收录，写法各不相同。我们要把它们整理成一份数据：每个抗体–抗原对只出现一次，带着它在所有来源里的全部测量，记作 3A = (antibody, antigen, affinity[])。难点有四处：

01

序列形态不一

有的来源给成熟 VH/VL，有的给带信号肽和 His-tag 的构建体、完整 IgG 重链或 scFv，有的只给 PDB 编号，或 parent 加突变名。

02

同一件事写了很多遍

去信号肽、去标签、去恒定区、拆 scFv，本质都是定位可变域边界，规格里却拆成了 7 条规则。

03

规则互相矛盾

一条规则要求先拆 scFv 再裁两端，另一条要求反过来。两种顺序实现出来，结果不同。

04

关键信息不在表里

实验用的是哪个抗原构建体、序列从哪来，常常只写在 README 或论文方法里，表里只有序列和 Kd。

I — Problem & Stance

Design Invariants

实现可以边做边调，但有四样东西从一开始就固定，因为它们决定了产出对不对。

Fixed
3A 形状
每个抗体–抗原对一条：(3A_ID, antibody, antigen, affinity[])。
测量五元组
每条测量记为 (label, assay, condition, replicate, lineage)，值照抄来源，不换算。
ID 公式
ID 只由清洗后的序列哈希得到，同一对分子在任何来源里 ID 都相同。
lineage 语法
每个值附一条来源记录：出自哪个文件、哪一行、哪一列，经过哪些处理。
Adjustable
中间表 缓存键 阶段划分
这四样定义了什么算「对」，其余只关系到怎么算出来。
II — Principles

Design Principles

每个来源配一个 adapter 负责读入，所有清洗交给共享模块。五条原则都围绕这个分工。

  1. Iadapter 要薄只读懂来源的格式，把原始行原样搬成统一的中间记录（record），不清洗，也不做生物学判断。→ 05
  2. II清洗只写一次裁剪、拆分、突变重建只在共享模块里实现，所有来源共用。→ 05
  3. III相同的输入只算一次先按输入去重再清洗，结果回填到每一行。→ 06
  4. IV运行结果可复现要读 README、论文才能判断的信息，运行前整理成带出处的决策文件；运行时只读文件，不调用 AI。
  5. V以产出为目标能得到有效 3A 就产出，排除只留给确实处理不了的记录。→ 07
II — Principles

Thin Adapter

N×M → N+M

来源格式各不相同，清洗规则却是通用的。把两者分开，工作量从「来源数 × 规则数」降到「来源数 + 规则数」。

  • 列名、分隔符、占位符、突变写法，这些来源差异全部在 adapter 里消化。
  • 共享模块按功能划分，内部不出现任何来源的名字。
  • 检验办法：一旦模块里要写「如果是某个来源就……」，就是划分错了。该改模块本身，而不是加分支。
II — Principles

Driven by Distinct Keys

大型数据集里，成千上万行常共用同一条序列，比如整个突变扫描库都针对同一个抗原。所以清洗不按行做，而按「不同的输入」做。

同一个输入只算一次

按清洗输入去重，每种输入对应一个去重键（distinct key）。每个键清洗一次，再按键 join 回每一行。图中 12 行只有 4 种输入，所以只算 4 次。

什么算「不同的输入」

来源边界、构建体标签、结构引用、待应用的突变会改变清洗结果，称为 evidence，计入键。名称、突变原文只用来记录出处，称为 notes，不计入键，否则同一条序列会因名字不同被重复计算。

突变扫描数据：两层键

有些来源只给一个 PDB 和大量点突变。第一层：每个 (结构, 链) 只恢复、编号一次 parent。第二层：点突变按编号落到 parent 上，沿用它的可变域边界。只有插入或缺失才重新编号。

II — Principles

Output First

目标是产出可用的 3A，而不是让每条记录都满足每一条规则。

规格里的排除条件，例如「找不到可变域就排除」，只是默认处理，不是必须执行的拒绝规则。

一个条件挡掉某个来源的大部分记录时，更可能是条件不适合这批数据。该调整的是处理方式，并把调整写进来源记录。

被排除的记录不会丢：排除日志记下原因和原始位置，条件改好后可以从原始数据直接重跑。

III — Data Flow

The Journey of a Record

一条原始数据行变成 3A，要经过四步。

  • 读入：adapter 把原始行拆成一条或多条中间记录（record），每条含抗体输入、抗原输入和若干测量。
  • 一行可能拆出多条，例如突变体和 WT、一个抗体对多个抗原，所以 record 按 (来源, 文件, 行号, 角色) 编号。
  • 分三支：抗体（AB）、抗原（AG）、测量（AFF）各自清洗。
  • 汇合 assemble：按 record 编号对齐三支，检查能否构成有效 3A，算出 3A_ID。
  • 合并 merge：跨来源按 3A_ID 分组，测量追加进同一个 affinity[]。
III — Data Flow

Asymmetric 3A Pathways

三支看似对称，处理方式并不一样：抗体和抗原需要共享模块，测量不需要。

没有跨行逻辑，就没有必要抽出模块。

抗体、抗原两支有跨行工作：很多行引用同一条序列，要先去重；裁剪、拆分、突变重建、结构读取都调用共享模块。

测量支只做行内工作：判断一个值算不算测量（空值、Fail 不算；n.b. 即检测不到结合，算一条定性测量），把一行的多个读数拆开，记下原始列名。不去重，不聚合，所以不设模块，在 adapter 里完成。

IV — Reconciling Specs

The Ledger Method

写模块之前，先把抗体、抗原、测量三份清洗规格逐条对照，做成一本台账，每条归入三类之一。

重叠
不同条目在说同一种操作，合并成共享模块。例如去信号肽、去标签、去恒定区、拆 scFv、判断链类型，都是「定位可变域」。
冲突
两条规则互相矛盾，逐条裁决。
缺口
规格没有覆盖、却必须有人负责的情况，给出默认处理。

重叠合并后得到 8 个共享模块；冲突和缺口的处理见下一页。

IV — Reconciling Specs

Conflict Rulings + Gap Handling

Conflict Rulings

scFv 先拆，还是先裁两端

两条规则对顺序的要求正好相反。我们改为一次找出序列里全部可变域区间，信号肽、标签、恒定区、linker 都是区间之外的部分，顺序问题随之消失。

合并时要不要判定重复测量

同一测量常被多个数据集转载，单位、舍入各不相同，无法可靠判等。裁决：不判定，不去重，每条测量带着来源记录追加进 affinity[]，由下游决定。

来源之间的依赖

补全只有 CDR 的数据时，规格允许去别的来源的处理结果里找 parent，来源之间因此要排队。裁决：切断依赖，每个来源只用自己的数据和明确引用的公开结构，可以单独重跑。

Gap Handling

突变属于哪一侧

两份规格都要求先判断，却没指定由谁做。现在由 adapter 按链字段分发到抗体或抗原侧，汇合时检查每个突变恰好被用一次。

一个抗原，多个结构

模型里结构只有一个位置。按来源优先级取一个，同级按 ID 字典序，其余写进来源记录。

结构怎么存

只存指针：结构 ID、文件位置和链映射，不复制坐标。

突变落在被裁掉的区段

例如突变在信号肽或标签里。裁剪后与 parent 完全相同，自然得到同一个 ID，位点写进来源记录。

V — Module Design

Eight Shared Modules

台账合并出 8 个共享模块。每个模块只做一类事，所有来源共用；红线表示模块之间的调用。

seqnorm
序列规范化

原始字符串 → 规范序列：统一大写、去空白，标出 gap 和非法字符，不可用则判为空。

vdomain
可变域定位

序列 → 全部可变域区间及链类型；信号肽、标签、恒定区、linker 由区间之外得出。合并了 7 条规则。

mutate
突变重建

parent + 突变列表 → 突变体序列，无法唯一重建时给出原因。抗体、抗原两侧共用。

structref
结构读取

结构 ID + 链 → 链序列、实际观察到的残基与编号。

antigen_bound
抗原片段

抗原链候选 + 构建体说明 → 实验实际使用的有序链列表。

resolve
证据择优

多个候选 + 优先级 → 选中项、全部候选与冲突标记。各处「来源 > 结构 > 工具 > 兜底」都用它。

ids
ID 生成

规范序列 → AB_ID、AG_ID、3A_ID，并做碰撞检查。

lineage
来源记录

键值 → key=value | … 格式的来源记录，所有模块共用。

V — Module Design

vdomain: Intervals as Output

可变域定位只输出一样东西：可变域在序列里的区间。信号肽、标签、恒定区、linker 都在区间之外，由区间推出，不存在先后顺序。

0

找不到可变域：不是抗体或无法定位，排除。

1

单个 VH、VHH 或 VL。左侧残余归为信号肽或标签，右侧归为标签或恒定区。

2

一条重链加一条轻链才算 scFv，中间须是合格的 linker。VL-linker-VH 方向互换后写入。

≥

两个同类区间或三个以上：不强行凑成一对，排除。

来源的重链栏、轻链栏本身也可能填错：

VHH 与其他只有重链的抗体统一写成 VH，轻链为空，类型只记在来源记录里。

V — Module Design

mutate and resolve

mutate · 突变重建
  • 很多数据只给 parent 和突变名（如 S31A），突变体序列要自己重建。
  • point：突变能唯一定位到 parent 上，且该位置的原残基与突变名一致，才接受。对不上就不猜，排除并记下原因。
  • region：只给了 CDR 片段时，在 parent 上按 IMGT 编号整段替换该区间，检查两侧框架和总长度，另一条链不变。
resolve · 证据择优
  • 同一个值常有几份候选。所有模块按同一顺序取：来源 > 结构 > 工具 > 兜底。
  • 同级候选不一致时，由调用方指定策略：pick_top 取第一个并记录冲突；reject 直接排除；tie-break 用额外规则定胜负，例如拆 scFv 时选两侧可变域都完整、剩余片段最短的切法。
  • 落选的候选不丢，全部写进来源记录。
